Audited: full clone of `prxtxks/UnderlyticsAI`, latest commit 2026-02-18. This document exists so the V2 rebuild never repeats these mistakes. Every finding is tied to specific code.

## 0. URGENT — Security

1. **A live GCP service-account private key is committed at the repo root** (`uxory-validation-1766743030496-469c9b895783.json`, real `BEGIN PRIVATE KEY` block). `.gitignore` covers `.env*` and `*.pem` but not `*.json`. The repo was made public. **Revoke the key immediately, re-privatize the repo, audit GCP usage logs.**

## 2. What V1 got RIGHT (carry forward)

1. **The grounding philosophy.** OCR/pdfplumber with bounding boxes and confidence scores; the LLM restricted to _label classification only — never arithmetic, never reading numbers_. This hard boundary is correct and stays.
2. **Cell-level lineage.** `cell_values.{source_document_id, source_page, source_row, confidence_score, is_override, original_value}` — the right audit spine. V2 formalizes it as the Fact Store.
3. **Learned mappings.** `line_item_mappings` with usage counts and fuzzy reuse drives LLM cost toward zero as label→taxonomy pairs accumulate. Keep, but tenant-scope it.
4. **Layered pipeline with idempotent, retry-safe orchestration.** Celery config was competent (acks-late, prefetch 1, purge-before-rerun). The _shape_ was right; the stages were weak.
5. **The design intent of validation.py** (subtotal reconciliation, YoY anomaly, duplicate periods) — correct ideas, just never enforced or surfaced.
6. **The visual identity.** Emerald/teal OKLCH palette, glassmorphism, violet computed-row accent, DSCR traffic-light colors. Palette is preserved verbatim in the blueprint (§8.1). One fix: `* { scrollbar-width: none }` globally hides scrollbars — remove inside data grids.

## 3. UX findings (dashboard restructure input)

- Workspace = toolbar + ONE mutually-exclusive 420px slide-in panel (Docs _or_ Pipeline _or_ Loan) + grid. Underwriting needs documents, spread, and loan inputs visible _simultaneously_ — the single-panel model forces constant toggling.
- Cell popover does double duty (override value + add addback) — two very different intents in one cramped surface.
- "Excel export" actually ships CSV with a misleading label.
- Addback classification is captured in UI then hardcoded to `"other"` at the API — data thrown away.
- No source-document verification view: users can't click a number and see where it came from, despite lineage existing in the DB. This is the single biggest missed trust feature.
- `template_analysis.txt` shows a real user need V1's annual-columns grid cannot represent: monthly-column operator forecasts (hotel RevPAR workbook). V2's period model must support monthly/quarterly/TTM/annual columns.
